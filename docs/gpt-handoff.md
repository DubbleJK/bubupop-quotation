## 1. 제품

직원용 인쇄 견적 웹앱. Next.js 16 App Router, React 19, TypeScript, Tailwind. 계산은 브라우저에서 한다. 관계형 DB는 없다.

품목 8개 (`src/config/products.ts`): POP, 스티커 시트, 스티커 솔벤트, UV아크릴키링, DTF, 티셔츠, 명함, 배너.

화면의 큰 숫자는 UV만 부가세와 수량 배율까지 넣은 최종가이다. 나머지 7개는 공급가(부가세 전)이다.

코드 기본 판매가는 `src/config/settings.ts`, `src/config/rates.ts`이다. UV 단가·배율만 `src/lib/calc/uvAcrylicKeyring.ts` 상수이다. 운영 KV나 브라우저에 다른 값이 있으면 화면 금액은 달라진다. 이 환경에는 KV 자격 증명이 없어 운영 값은 읽지 않았다.

## 2. 1차 안정화에서 이미 한 일

판매 공식은 바꾸지 않았다. 설정이 어긋나거나 PIN이 공개 응답에 섞이던 부분만 고쳤다.

- 견적 금액은 `/api/config` 응답을 받은 뒤에만 표시한다. 서버에 닿지 못하면 브라우저의 옛 설정으로 금액을 만들지 않는다.
- 서버가 저장본 없음(404)이라고 한 뒤에만 브라우저 저장값, 그것도 없으면 코드 기본값을 쓴다. 화면에 출처와 버전을 표시한다.
- 서버 저장 실패 시 localStorage에 쓰지 않고 성공으로 표시하지 않는다. KV가 없으면 저장 API는 `503`, `persisted: "none"`.
- 구버전 JSON에 `configMeta`가 없으면 버전 0. 서버 저장 성공 시에만 저장된 버전을 1 올린다. 클라이언트가 보낸 버전은 무시한다.
- 공개 `GET /api/config`는 `loginPin`을 제거한다. 관리자 `GET /api/admin/config`만 로그인 쿠키가 있을 때 PIN을 포함한다.
- 로그인은 `POST /api/admin/login`이다. 세션은 `HttpOnly` 쿠키 `quotation_admin_session`. 예전 localStorage 값 `"1"`만으로는 관리자에 들어갈 수 없다.
- 저장 인증은 쿠키이다. 화면의 PIN 칸은 저장할 새 PIN이지, 저장 요청의 비밀번호가 아니다. 칸이 비어 있으면 기존 PIN을 유지한다.
- 프로덕션에서 `ADMIN_SESSION_SECRET`(16자 이상)이 없으면 로그인은 503이다. 로컬 개발은 이 변수가 없어도 된다. 예시는 `.env.local.example`.
- 자동 테스트: `npm test` 35개 통과. `npm run build` 통과.
- 로컬 브라우저에서 POP 200×200mm 10장은 4-cut 공급가 126,900원, 부가세 12,690원, 총액 139,590원, 2-cut 공급가 110,090원으로 변경 전과 같았다.
- 클라이언트 빌드 묶음에서 기본 PIN 문자열은 나오지 않았다.

검증 명령:

```powershell
cd C:\Users\USER\quotation-app
npm test
npm run build
node scripts/backup-public-config.mjs
node scripts/check-client-pin.mjs
```

백업 스크립트는 KV 자격 증명이 없으면 네트워크 호출 없이 끝난다.

## 3. 설정이 적용되는 순서

구현: `src/lib/config/resolveQuoteConfig.ts`, `src/lib/config/localProvider.ts`, `src/app/api/config/route.ts`.

1. `GET /api/config`가 200이면 그 공개 설정이 견적의 기준이다. 브라우저 저장값보다 우선한다.
2. 404이면 서버 저장본이 없는 것이다. 그 다음에만 `localStorage` 키 `quotation_admin_config`, 없으면 코드 기본값.
3. 네트워크 오류나 5xx이면 견적 금액을 그리지 않는다.
4. KV 자격 증명이 없으면 클라이언트를 만들지 않는다. 상태만 보는 API는 `GET /api/config/status`이며 가격과 PIN을 반환하지 않는다.
5. 공개 캐시를 브라우저에 쓸 때는 `toPublicConfig()`로 PIN을 뺀다.

공통 반올림 (`src/lib/calc/common.ts`): `Math.round(금액 / 10) * 10`. 부가세와 총액도 각각 10원 반올림. UV는 이 함수를 쓰지 않고 1원 `Math.round`를 쓴다.

## 4. 현재 판매 공식 (코드 기본값)

이 숫자는 아직 유효한 판매가다.

공통 부가세율 0.1. 스티커 기본 간격 5mm. 재단 여백 5mm. 스티커 최소 공급가 20,000원. 시트 작업비 15,000원. 솔벤트 작업비 15,000원. 시트 컷팅 30초/장(금액에 미포함).

### POP — `calcPop` `src/lib/calc/pop.ts`

롤 폭 610mm. 4-cut 63,452원/m. 2-cut 55,046원/m. 간격 없음. 폭 방향 매수를 세지 않는다.

1. 폭과 높이가 모두 롤 폭보다 크면 에러 `폭 초과(610mm) - 사이즈 확인`, 금액 0. 문구의 610은 글자로 고정돼 있다.
2. 한 장 길이 = 양쪽이 롤 이하면 짧은 변, 폭만 들어가면 높이, 높이만 들어가면 폭.
3. 길이(m) = 한 장 길이 / 1000 × 수량.
4. 공급가 = 길이 × 해당 단가, 10원 반올림. 큰 숫자는 4-cut 공급가.

확인값: 200×200mm 10장 → 2.00m, 4-cut 126,900 / 부가세 12,690 / 총액 139,590, 2-cut 110,090. 50×50mm 10장 → 0.50m, 4-cut 31,730.

### 스티커 시트 — `calcStickerSheet` `src/lib/calc/stickerSheet.ts`

재질 단가(원/장): 아트지·모조지 A4 500 A3 980, 유포지 A4 950 A3 2,100, 투명데드롱 A4 950 A3 사용 안 함.

용지 A4 210×297, A3 297×420. 사방 5mm를 뺀 배치 영역은 A4 200×287, A3 287×410.

1. 한 칸 = 스티커 변 + 간격. 마지막 칸 뒤 간격도 포함. 가로/세로 배치 중 많은 쪽. 0이어도 최소 1.
2. 장수 = 수량 / 장당 개수, 올림.
3. 공급가 = max(15,000 + 장수 × 단가, 20,000), 10원 반올림.
4. 화면의 큰 숫자는 A4 공급가.

확인값: 아트지 50×50mm 50매 간격 5mm → A4 장당 15, 4장, 공급가 20,000, 부가세 2,000, 총액 22,000.

### 솔벤트 — `calcStickerSolvent` `src/lib/calc/stickerSolvent.ts`

롤 폭 620mm. 미터 단가는 별도 필드가 없고 POP 4-cut `popSellPerM4` 63,452원/m.

1. 두 방향 중 더 짧은 길이. 폭 방향 개수 0이면 1로 올린다.
2. 길이(mm) = 줄 수 × (진행 변 + 간격). 마지막 뒤 간격 포함.
3. 공급가 = 15,000 + 길이(m) × 63,452, 10원 반올림. 최소금액 없음.

확인값: 50×50mm 100장 간격 5mm → 0.55m, 공급가 49,900, 부가세 4,990, 총액 54,890.

### UV아크릴키링 — `calculateQuote` `src/lib/calc/uvAcrylicKeyring.ts`

관리자 설정과 `settings.vatRate`를 쓰지 않는다.

1. 면적(㎠) = 가로 × 세로 / 100.
2. 수량 1: 면적 8.4 이하 5,800, 초과 6,000.
3. 수량 2 이상 개당 공급가 = round(기본금 + 면적 × 계수).

| 수량 | 기본금 | 계수 |
|---|---:|---:|
| 2~10 | 1700 | 13.7 |
| 11~50 | 1195 | 14.8 |
| 51~100 | 1145 | 14.1 |
| 101~200 | 1069 | 14.0 |
| 201~300 | 1053 | 13.6 |
| 301~400 | 1040 | 13.5 |
| 401~500 | 1030 | 13.56 |
| 501+ | 1013 | 13.61 |

4. 공급가 합계 = 개당 × 수량.
5. 부가세 = round(합계 × 0.1) 1원 단위.
6. 최종가 = round((합계 + 부가세) × 배율).

| 수량 | 배율 |
|---|---:|
| 1~10 | 1.10 |
| 11~49 | 1.07 |
| 50~200 | 1.05 |
| 201~299 | 1.02 |
| 300+ | 0.99 |

파일에 적힌 검증 최종가: 45×30 1개 7260, 45×30 100개 154193, 47×47 200개 318318, 50×50 500개 745421, 47×47 1000개 1430946.

### DTF — `calcDtf` `src/lib/calc/dtf.ts`

롤 850mm, 간격 7mm, 판매 13,900원/m, 참고 원가 1,350원/m(판매가에 더하지 않음), 5분/m(판매가에 더하지 않음).

1. 두 방향 중 짧은 길이. 그 방향이 롤보다 크면 길이는 Infinity.
2. 한 줄 개수 = floor((롤+간격)/(조각+간격)), 최소 1. 간격은 조각 사이에만.
3. 길이(mm) = 줄×진행크기 + (줄-1)×간격.
4. 공급가 = 길이(m) × 13,900, 10원 반올림.
5. 여러 디자인은 줄 공급가를 더한 뒤 부가세를 한 번만 계산한다 (`src/components/forms/DtfForm.tsx`).

확인값: 100×100mm 10장 → 0.207m, 공급가 2,880, 부가세 290, 총액 3,170, 참고 원가 280. 100×80×3과 200×150×2 → 공급가 1,110과 2,090, 합산 부가세 320.

### 티셔츠 — `calcTshirt` `src/lib/calc/tshirt.ts`

반팔 18,000, 긴팔 20,000, 후드 25,000, 윈드브레이커 35,000. 2XL 이상 1장 3,000원. 관리자 화면에 입력칸은 없다. 값은 설정 JSON에는 들어 있다.

할인 배열 앞에서 처음 맞는 구간: 100장 25%, 50장 20%, 10장 10%.

공급가 = (단가×수량 + 2XL수량×3,000) × (1-할인율), 10원 반올림. 할인은 한 번이며 추가금까지 포함한 합계에 곱한다.

확인값: 반팔 10장 중 2XL 2장 → 167,400. 후드 100장 중 2XL 10장 → 1,897,500, 할인 0.25.

### 명함 — `calcBusinessCard` `src/lib/calc/businessCard.ts`

크기 계산 없음. 수입 당일제 100매 20,000, 200매 25,000. 아트지 500매 15,000. 디자인: 출력만 0, 베이직 8,000, 스탠다드 20,000, 프리미엄 30,000.

공급가 = 인쇄비 + 디자인비, 10원 반올림. 표에 없는 매수는 인쇄비 0. 현재 폼은 등록된 매수만 고른다.

확인값: 수입 당일제 100매 베이직 → 공급가 28,000, 총액 30,800.

### 배너 — `calcBanner` `src/lib/calc/banner.ts`

크기 입력 없음. 출력 22,000원/장, 실내 거치대 15,000, 실외 거치대 28,000.

확인값: 출력 1장 → 22,000. 출력 2 + 실내 1 + 실외 1 → 87,000.

## 5. 아직 남아 있는 계산 결함

`tests/known-defects.test.ts`가 현재 동작을 고정한다. 이 기대값은 올바른 정책이 아니다. 식을 고치면 이 테스트가 실패해야 하고, 그때 기대값을 정상 규칙으로 바꾼다. `tests/quote-baseline.test.ts`의 정상 입력 금액은 식을 유지하는 동안 깨지면 안 된다.

- UV 45×30mm 최종가: 1개 7,260 → 2개 4,562, 10개 22,809 → 11개 18,062, 100개 154,193 → 101개 146,752.
- 티셔츠 반팔: 9장 = 10장 = 162,000. 49장 793,800 > 50장 720,000.
- 스티커 300×300mm 2매: 용지보다 큰데도 장당 1개, A4·A3 공급가 각 20,000. 에러 없음.
- 솔벤트 700×800mm 2장: 롤 620mm를 넘는데도 1.41m, 공급가 104,470. 에러 없음.
- DTF 900×900mm 1장: 공급가·길이가 Infinity. 폼이 에러로 바꾸지 않는다.
- 명함 함수에 300매를 직접 넣으면 인쇄비 0, 공급가 8,000. 화면 선택지에는 300매가 없다.

POP은 한 장 길이 × 수량이다. 200×200mm 10장을 폭에 3장씩 넣는 비교 배치는 0.80m이지만, 그 비교식은 앱에 없다. 현장 공정이 한 줄 재단인지 확인되기 전에는 POP 길이 식을 바꾸지 않는다.

## 7. 테스트로 가격 변경을 판정하는 방법

2. 고친 뒤 `tests/quote-baseline.test.ts`에서 의도적으로 바뀐 케이스만 기대값을 수정한다. 나머지 정상 입력은 이전 금액과 같아야 한다.
3. `tests/known-defects.test.ts`에서 없어진 결함은 삭제하거나 정상 기댓값으로 교체한다. 결함 테스트를 통과시키기 위해 판매가를 슬쩍 바꾸지 않는다.
4. 전후 비교표에는 입력, 이전 공급가, 새 공급가, 이전 총액, 새 총액을 적는다.
